## 操作例

1. 従来どおり採算シミュレーションで業種を選び、見積入力と該当業種の原価を変更します。
2. 売上分析を開き、業種「農家」、対象年2026、開始月4、終了月9に変更します。
3. KPI、グラフ、ヒートマップが同じ条件で変化します。売上履歴は現在の見積に合算しません。
4. 見積入力F16を負数にすると入力規則が拒否します。貼付などで不正値が入った場合も入力検査とD12が警告します。
5. 未使用業種の原価シートを削除する運用は維持。残す業種を採算シミュレーションで選択し、設定の不要業種を行ごと削除してから原価シートを削除します。

売上分析の業種選択は販売履歴の絞込みであり、原価参照の選択とは独立です。原価シートを削除しても履歴を消しません。業種別配布では不要な履歴と売上分析B5の選択肢も手動で整理してください。

## 計算の範囲

予定案件利益＝試算売上−選択業種の試算原価（案件共通費込み）。入力されていない間接費は含みません。会計上の売上総利益・営業利益とは限りません。

売上分析の「計上原価控除後差額」は、履歴の税抜売上から履歴の計上原価だけを差し引いた金額です。共通費の配賦はしません。現在案件の予定利益とは別指標です。

販売10明細、原価40明細/業種は従来の上限です。履歴は576行の固定範囲です。表の外へ追記しても集計範囲は自動拡張されません。実運用での継続追記対応は次の要件判断とします。

## スライサー／タイムラインの検討結果

今回は共通入力セルとSUMIFSで連動を実装しています。Excel標準のスライサー・タイムラインは未実装です。

標準UIを採用する場合、売上データの同一ソースから共通キャッシュのピボットテーブルを作り、業種・商品のスライサーと日付タイムラインを全ピボットへ接続します。Windows側でOpenCodeから作成し、選択／解除・更新・保存再起動・ヒートマップとの一致を検証する方式を推奨します。購入者のVBA有効化は不要にできますが、データ変更後のピボット更新操作が必要になります。

現方式は数値入力だけで再計算し更新操作不要です。ネイティブ方式は複数選択・期間ドラッグの操作性が優れます。今回の完成品とネイティブ方式を混同しないでください。

- https://support.microsoft.com/en-us/excel/get-started/use-slicers-to-filter-data

## 添付3のおすすめ順

1. **商品別スパークライン**：ヒートマップ右端に12か月推移を追加。繁忙期と弱い月を商品ごとに比較できます。ヒートマップと同じフィルターを適用し、期間外を欠損として扱う設計が適切です。
2. **売上目標達成ゲージ**：月別・業種別の目標入力表を用意してから追加。選択期間の売上÷同じ期間の目標で計算し、0円目標は算出不可。例えば目標500万円・売上360万円なら72%。目標利益率とは別指標です。
3. **費用のON/OFF**：配送・広告等が実際に不要になる条件だけに限定。既発生費用・必須費用まで除外すると判断を誤るため、初期版では優先しません。採用時は除外項目と除外額を必ず結果に表示します。

添付3は推薦依頼のため、この3機能は今回未実装です。

## 検証と互換性

計算エンジンの40テストは合格。Excel実機未検証。INDIRECTは検証エンジンが非対応のため、検証時だけ直接参照に置換して計算し、配布ファイルには元のINDIRECTを復元しています。従って削除耐性の実機保証ではありません。

機能別の公式資料対象範囲と最古の動作保証版は別です。今回はSUMIFS、IF等、標準グラフ、条件付き書式、入力規則、従来形式のメモを使用。Excel 2024／Microsoft 365を実機評価の第一対象とし、古い版を含む最古の全機能保証版・一部機能保証版はまだ確定していません。2024固有の関数を装飾目的で追加していません。

同梱test_report.mdとWindows検証スクリプトを参照してください。

## 再ビルド（開発者向け）

既存v0.1のbuild.mjsを改修し、enhance.mjsを追加しています。成果物とソースを同梱しています。

1. artifact-toolを利用可能な作業環境でPROTOTYPE_OUTPUT_DIRを出力ディレクトリに設定。
2. Nodeでbuild.mjs実行（enhance.mjsも同じディレクトリ）。
3. Python標準ライブラリでfinalize_ooxml.py実行。
4. Windows版Excelでverify_excel_windows.pyおよびverify_v02_windows.py実行。

スクリプトのPython利用は開発・検証用です。購入者にインストールは不要です。最終OOXML処理は、INDIRECT復元、印刷設定、全セルロック解除、メモを非表示化、既存スライダーとメモのVML統合を行います。

## セットアップ（開発者向け）

仮想環境はプロジェクト直下の `.venv` とする。対象シェルを明記する。

| 目的 | PowerShell | コマンドプロンプト（cmd） |
|---|---|---|
| 仮想環境の作成 | `python -m venv .venv` | `python -m venv .venv` |
| 仮想環境の有効化 | `.\.venv\Scripts\Activate.ps1` | `.\.venv\Scripts\activate.bat` |
| pywin32 の導入 | `python -m pip install pywin32` | `python -m pip install pywin32` |
| 有効化の確認 | `python -c "import win32com.client; print('OK')"` | `python -c "import win32com.client; print('OK')"` |

PowerShell で実行ポリシーにより有効化できない場合は、`Set-ExecutionPolicy -Scope Process Bypass` を実行してから有効化する。
