# 要件定義（ExcelBIBasic3）

- 版: RevA
- 作成日: 2026-10-21
- 対象: `prototype.xlsx`（ExcelBIBasic2 試作、SUMIFS 版）の再設計

## 1. 目的
- 見積・原価・利益シミュレーターを、BI ツール風のダッシュボードへ再設計する。
- 売上分析は Power Query とデータモデルへ移行し、スライサーとタイムラインで全表示を連動させる。
- 見積・原価・利益の即時再計算は関数で維持し、購入者がマクロなしで使える `.xlsx` を提供する。

## 2. 背景と現状
- 現行ブックは 11 シート、売上データ 576 行（2025-01 から 2026-12 の 24 か月 × 8 商品 × 3 件）、メモ 74 件、`INDIRECT` 24 件である。
- 売上分析は `SUMIFS` と手入力の対象業種・対象年・開始月・終了月で構成され、ピボットテーブル、スライサー、タイムラインは存在しない。
- グラフは 5 個（採算シミュレーション 2、売上分析 3）である。
- 実測値は `package_checks.json`、`notes_manifest.json`、`sales_fixture.json`、`engine_tests.json` に記録済みである。

## 3. 対象範囲
- 売上分析の再構築（Power Query、データモデル、ピボットテーブル、ピボットグラフ、スライサー、タイムライン、KPI、ヒートマップ、スパークライン、ゲージ、チェックボックス）。
- 見積入力の備考欄復帰と状態表示の整理。
- 採算シミュレーション D12 の状態表示一元化。
- 商品マスタの別テーブル化。
- 作業管理文書と仕様書一式の整備。

## 4. 対象外
- 返品、返金、複数税率の混在計算、年度締め処理。
- VBA、ActiveX、マクロブック。
- 外部データソース、外部リンク、Web クエリ。
- 会計上の粗利・営業利益の算出（現行どおり区別を明記する）。
- 参考画像のピクセル単位の再現。

## 5. 用語
| 用語 | 意味 |
|---|---|
| PT | ピボットテーブル |
| PG | ピボットグラフ |
| データモデル | Power Pivot のデータモデル（ブック内の列指向モデル） |
| DAX メジャー | データモデル上で定義する集計式 |
| CUBEVALUE | データモデルを参照する CUBE 関数 |
| タイムライン | 日付軸のスライサー |
| 万円表示 | 保存値（円）を 10000 で除して四捨五入した表示 |

## 6. 機能要件

### 6.1 データ基盤
| ID | 要件 | 根拠 |
|---|---|---|
| FR-001 | 売上データシートのテーブル `SalesHistory`（A4:I580、576 行）を Power Query で取り込み、データモデルへロードする | 売上分析の基盤 |
| FR-002 | 商品マスタを別テーブル化する。列は商品 ID、商品名、業種、表示順、有効とする | 商品追加への対応 |
| FR-003 | 日付マスタを Power Query で生成する。範囲は 2025-01-01 から 2026-12-31 とする。列は日付、年、月、年月、年月表示とする | タイムラインと前年比の基盤 |
| FR-004 | リレーションを設定する。売上[商品] から 商品マスタ[商品名]、売上[日付] から 日付マスタ[日付] とする | モデル整合 |
| FR-005 | DAX メジャーを定義する。売上、計上原価、差額、差額率、前年差額、前年比、件数とする | KPI とグラフの値 |

### 6.2 表示と操作
| ID | 要件 | 根拠 |
|---|---|---|
| FR-006 | PT を配置する。月別推移、商品別、業種別、KPI、商品×年月マトリクス（予備）、ゲージ用（独立）とする | ダッシュボード構成 |
| FR-007 | PG を配置する。月別推移（折れ線）、前年比較（棒）、商品別（横棒）、業種構成（ドーナツ）とする | 参考画像の構成 |
| FR-008 | スライサー（業種、商品）を配置し、ゲージ用を除く全 PT と全 PG へ接続する | 商品スライサー必須 |
| FR-009 | タイムライン（日付、年月粒度）を配置し、ゲージ用を除く全 PT と全 PG へ接続する | 期間の連動 |
| FR-010 | KPI を 4 表示とする。税抜売上、計上原価控除後差額、差額率、前年比とする。スライサーとタイムラインへ連動する | 同一条件表示 |
| FR-011 | ヒートマップを商品×年月の固定格子で構成する。万円表示、3 色スケール、0 円・データなし・選択範囲外の 3 状態表示とする | 参考画像 2 |
| FR-012 | 商品行ごとにスパークラインを配置する。参照範囲はヒートマップの万円値とする | 参考画像 3 |
| FR-013 | 目標達成ゲージを配置する。入力は業種、開始年月、終了年月とし、目標テーブル、実績集計、データバーで構成する | 参考画像 3 |
| FR-014 | ゲージはスライサーとタイムラインへ連動しない。その旨を画面に明記する | 評価期間の独立性 |
| FR-015 | チェックボックスをフォームコントロールで配置する。試算条件を切り替え、リンクセルは制御用セルとする | 参考画像 3 |

### 6.3 既存機能の改訂
| ID | 要件 | 根拠 |
|---|---|---|
| FR-016 | 見積入力 B12:F12 を備考入力へ復帰する。D12:F12 の状態表示と条件付き書式 3 規則を削除する | 入力欄の復帰 |
| FR-017 | 状態表示は採算シミュレーション D12 のみとする。正常、未達、異常の 3 状態を色分けする | 状態の一元化 |
| FR-018 | 見積、原価、税、値引、目標の計算セルと丸めを維持する（計算仕様に準拠） | 既存機能の保全 |
| FR-019 | メモは既存 74 件を維持する。削除禁止とし、追加は新規要件に限る | 引き継ぎ |
| FR-020 | `INDIRECT` は 24 件を維持する | 既存機能の保全 |
| FR-021 | シート保護、セル保護、ウィンドウ枠固定を行わない | 購入者の編集自由 |
| FR-022 | VBA、外部リンク、マクロを含めない | 配布要件 |
| FR-023 | 業種の追加と削除の運用手順を文書化する。追加時は設定シートと計算 B4 の参照範囲を拡張する | 運用保守 |
| FR-024 | データ更新は「すべて更新」1 操作で完結する。CUBE 関数は自動再計算とする | 操作簡素化 |
| FR-025 | 再ビルド工程で同一の成果物を再生成できる | 再現性 |

## 7. 非機能要件
| ID | 要件 | 備考 |
|---|---|---|
| NFR-001 | スライサー操作から全表示更新まで 3 秒以内を目標とする | 実測対象 |
| NFR-002 | 対応版は compatibility_matrix.md の範囲とする。機能的下限は Excel 2016 Professional Plus、推奨下限は Excel 2024 Professional Plus または Microsoft 365 Apps | 実機保証なし |
| NFR-003 | 万円表示の丸め誤差は最大 ±0.5 万円とする | 表示仕様 |
| NFR-004 | 表示言語は日本語とする。配色は設計仕様のパレットに統一する | 参考画像準拠 |
| NFR-005 | 公開禁止情報、外部リンク、認証情報を含めない | 配布要件 |
| NFR-006 | 実機未検証の範囲を明示する | 品質表示 |
| NFR-007 | 操作説明を画面とメモに記載する。マニュアル依存を最小化する | 保守性 |

## 8. 受入基準
| ID | 基準 | 対応要件 |
|---|---|---|
| AC-01 | スライサー（業種、商品）とタイムラインの変更で KPI、3 グラフ、ヒートマップ、スパークラインが同一条件で更新される | FR-008、FR-009、FR-010、FR-011、FR-012 |
| AC-02 | KPI 値がデータモデルの DAX 集計値と一致する | FR-005、FR-010 |
| AC-03 | ヒートマップの表示が万円形式であり、3 状態が区別される | FR-011、NFR-003 |
| AC-04 | ゲージがスライサー非連動で動作し、達成率と残額が入力条件と一致する | FR-013、FR-014 |
| AC-05 | チェックボックスの切替で試算側の値のみが変化し、確定側は変化しない | FR-015、FR-018 |
| AC-06 | 見積入力 B12:F12 が備考入力として機能し、状態表示が採算 D12 のみとなる | FR-016、FR-017 |
| AC-07 | メモ 74 件と `INDIRECT` 24 件が維持される | FR-019、FR-020 |
| AC-08 | 保護、固定枠、VBA、外部リンクが存在しない | FR-021、FR-022 |
| AC-09 | 「すべて更新」1 操作で全表示が最新化される | FR-024 |
| AC-10 | 再ビルド工程で同一ハッシュの成果物が再生成される | FR-025 |

## 9. 制約と前提
- 作業環境は Windows とする。
- 実機検証は pywin32 と Excel デスクトップアプリを用いる（`.venv` に導入）。
- 参考画像 3 点は構成と配色の参考であり、保存は行わない。
- データモデル機能は Excel のエディションに依存する。互換性は対応版表で管理する。
