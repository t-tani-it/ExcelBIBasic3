# デザインバリアント要求（ExcelBIBasic3）

- 版: RevA
- 作成日: 2026-10-22
- 用途: 別セッション・別モデルが、v0.4 と同一機能のまま異なるデザインの Excel ブックを作成するための要求
- 対象: `prototype_v04.xlsx` を出発点とする別成果物
- 優先順位: `AGENTS.md`、`docs/decision_log.md` の D-22、D-24、D-25、D-26、本要求、`docs/v0.4_method_a_addendum.md`

## 0. この文書の使い方

- 別セッション・別モデルは、最初に `AGENTS.md`、`docs/document_index.md`、`docs/decision_log.md` の D-22、D-24、D-25、D-26、`docs/v0.4_method_a_addendum.md`、本要求、`docs/test_spec.md` 第17節を読む。
- 本要求は、v0.4 とは別ファイルの成果物に適用する。v0.4 のブックと文書を上書きしない。
- 本要求の固定要件は変更しない。デザイン可変要件の範囲で独自の設計を提案する。
- 優れた UI があれば採用してよい。ただし、固定要件を壊さず、採用元、採用理由、ライセンスを設計書へ記録する。
- 判断に迷う事項は、実装前に質問する。無断で固定要件を変更しない。

## 1. 目的

- v0.4 と同じ機能を持つ Excel ブックを、異なる UI とレイアウトで作成する。
- `売上分析` シートは v0.4 のセル、書式、グラフ、ヒートマップ、スパークライン、スライサー、タイムラインを流用せず、0 から再作成する。
- 既存の見積・原価・利益シミュレーターは維持する。売上分析だけを新しいデザインへ置き換える。
- 機能の同一性と、デザインの差分を、検証結果と設計書で説明できる状態にする。

| 成果物 | 内容 | 必須 |

| 検証結果 | 自動検証の結果と、手動確認の未実施範囲 | 必須 |
| 既知の問題 | 制約、未実装、未検証、設計上の判断 | 必須 |

| 引き継ぎ | コンテキスト 0% から再開できる手順 | 必須 |

- 成果物は v0.4 と別ファイルとする。
- 文書は v0.4 の `docs` を上書きせず、別フォルダまたは別ファイル名で保存する。
- ブック、文書、ログにローカルパス、APIキー、個人ID、認証情報を含めない。

## 3. 出発点と売上分析シートの再作成

### 3.1 出発点

- `prototype_v04.xlsx` を複製して作業を開始する。
- 売上分析以外の既存 10 シート、商品マスタ、売上データ、計算式、メモ 74 件、`INDIRECT` 24 件を維持する。
- 制御シートは維持または同等の作業用シートへ置換してよい。作業用シートの追加・非表示は可とする。
- `売上分析` シート以外の既存シートは、固定要件に反しない限り変更しない。

### 3.2 売上分析シートの再作成

- 既存の `売上分析` シートを削除する。
- 同名の `売上分析` シートを新規作成する。
- 旧シートのセル、書式、結合、入力規則、条件付き書式、図形、グラフ、スパークライン、印刷設定を継承しない。
- 旧シートに付随するスライサー、タイムライン、ピボットグラフ、スパークライン、条件付き書式を整理する。
- 既存の `制御` シートの PT と共有キャッシュは維持する。必要に応じて再作成する。
- `売上分析` シートのセル番地は自由とする。ただし、他シートからの参照がないことを確認する。
- シート名は `売上分析` を維持する。

### 3.3 UI の採用方針

- v0.4 の UI をそのまま複製することを要求しない。
- 優れた UI があれば採用してよい。採用元が外部の場合は、ライセンスと再配布条件を確認する。
- 採用した UI の出典、採用理由、v0.4 からの差分を設計書へ記録する。
- 色だけで状態を伝えない。状態の文字、記号、注記を併用する。
- 固定要件を壊す UI 変更は行わない。

## 4. 固定要件

### 4.1 成果物と配布

| VR-F-04 | 公開禁止情報、ローカルパス、APIキー、個人ID、認証情報を含めない |

### 4.2 既存機能の維持

| ID | 要件 |
|---|---|
| VR-F-05 | 見積、原価、税、値引、目標、利益の計算セルと丸めを維持する |
| VR-F-06 | 見積入力 B12:F12 の備考入力を維持する |
| VR-F-07 | 状態表示は採算シミュレーション D12 を正とする |

### 4.3 データ基盤

| ID | 要件 |
|---|---|
| VR-F-11 | `SalesHistory` は 576 行、2025-01 から 2026-12、8 商品、各月各商品 3 件とする |
| VR-F-12 | `SalesHistory` の列は、日付、業種、商品、数量、税抜単価、税抜売上、計上原価、計上原価控除後差額、データ区分、年月、年、月とする |
| VR-F-13 | 商品マスタは別テーブルとし、商品ID、商品名、業種、表示順、有効を持つ |
| VR-F-14 | 商品マスタは方式Aでは PT とスライサーに接続しない |
| VR-F-15 | 商品スライサーは `SalesHistory[商品]` を使用する |
| VR-F-16 | 商品を追加する場合は、商品マスタと売上データの両方へ登録する |

### 4.4 集計方式

| ID | 要件 |
|---|---|
| VR-F-17 | 方式Aを維持する。通常の PT、共有キャッシュ 1 個、スライサー、タイムライン、ピボットグラフを使用する |
| VR-F-18 | Power Query、データモデル、DAX、リレーション、CUBE 関数を使用しない |
| VR-F-19 | すべての PT は 1 個の共有キャッシュを参照する |
| VR-F-20 | 現在期間の PT とグラフは、業種・商品スライサーと日付タイムラインへ接続する |
| VR-F-21 | 前年比較の PT とグラフは、業種・商品スライサーへ接続し、日付タイムラインへ接続しない |
| VR-F-22 | 前年比は 2026 年と 2025 年の比較を維持する。可変の年次比較へ変更する場合は、別要件として提案する |
| VR-F-23 | タイムライン初期値は 2026-01-01 から 2026-12-31 とする |
| VR-F-24 | 2025 年のヒートマップ列は、タイムラインを全期間へ広げるまで空欄とする |

### 4.5 ダッシュボード

| ID | 要件 |
|---|---|
| VR-F-25 | KPI は 4 表示とする。税抜売上、計上原価控除後差額、差額率、前年比とする |
| VR-F-26 | KPI は円表示とする。差額率と前年比はパーセント表示とする |
| VR-F-27 | ピボットグラフは 4 個以上とする。月別推移、前年比較、商品別、業種構成に相当する情報を表示する |
| VR-F-28 | 商品×年月のヒートマップを 8 商品 × 24 か月で表示する |
| VR-F-29 | ヒートマップは万円表示とする。値は `ROUND(円/10000,0)` と `0"万円"` を使用する |
| VR-F-30 | スパークラインを商品行ごとに 8 本配置する。参照範囲はヒートマップの万円値とする |
| VR-F-31 | ヒートマップの 0 円、データなし、選択範囲外を区別する。`IFERROR` による一律の空欄化を行わない |
| VR-F-32 | 0 円は `0万円`、データなしは `－`、選択範囲外は空欄と塗りなしを基本とする |
| VR-F-33 | 売上分析の注記に、差額の定義、会計利益との区別、架空データである旨を表示する |
| VR-F-34 | 商品マスタ未接続の旨と、商品追加時の売上データ登録を注記する |

## 7. 検証方法

- `verify_v04_windows.py` を参考に、バリアント用の検証スクリプトを作成する。
- 検証項目は、シート、テーブル、共有キャッシュ、PT、スライサー、タイムライン、KPI、ヒートマップ、スパークライン、既存計算、メモ、`INDIRECT`、保護、外部リンク、クエリ、公開禁止情報を含む。
- 数値の期待値は `sales_fixture.json` と `windows_v04_results.json` を参考にする。
- ヒートマップの 3 状態は、0 円、データなし、選択範囲外を個別に検査する。
- 前年比較の PT がタイムラインで変化しないことを検査する。
- 業種・商品スライサーが全 PT に接続していることを検査する。
- デザイン差は、設計書の比較表と実ファイルの目視で確認する。
- 自動検証で確認できない手動操作、印刷、性能は「未検証」と記録する。生成成功だけで合格としない。

## 8. 禁止事項

- `prototype_v04.xlsx` を上書きしない。
- 既存の見積・原価・利益の計算式を変更しない。
- メモ 74 件を削除しない。
- `INDIRECT` 24 件を削除しない。
- Power Query、データモデル、DAX、リレーション、CUBE 関数を追加しない。
- VBA、ActiveX、外部リンク、外部接続を追加しない。
- シート保護、セル保護、ウィンドウ枠固定を追加しない。
- `IFERROR` でヒートマップのエラーを一律に隠さない。
- 未検証の対応版を保証しない。
- ローカルパス、APIキー、個人ID、認証情報を文書・ログ・成果物へ含めない。

## 9. 既知の制約

- v0.4 のヒートマップは `IFERROR` で空欄化しており、3 状態の完全な区別は未実装である。バリアントでは改善する。
- v0.4 の商品マスタは PT 未接続である。バリアントでも方式Aの制約を維持する。
- v0.4 の前年比は 2026 年と 2025 年の固定比較である。バリアントでも維持する。
- v0.4 のヒートマップは 8 商品である。商品名の数式は `商品マスタ!B5:B24` の余白を参照するが、表示行は 8 行であり、20 行の表示は未実装である。
- ゲージ、目標テーブル、チェックボックスは未実装である。
- 手動 UI、印刷、性能は未検証である。
- 対応版は Microsoft 365 のみ実機確認済みである。他の版は未検証である。
