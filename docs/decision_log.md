## D-22 データモデル方式の実行不能（実測）

| 項目 | 内容 |
|---|---|
| 決定 | 本ビルド環境では Power Query のデータモデル接続を作成しない。売上分析は v0.2 の SUMIFS 版を維持し、Power Query・データモデル・ピボット化は別環境での再実装とする |
| 根拠 | `Connections.Add2(..., CreateModelConnection=True)` と `Model.Refresh` が、`Excel.CurrentWorkbook()` を参照するクエリの評価時に応答しない。Excel 内部マクロ、`Application.OnTime`、可視インスタンスのいずれでも同一現象 |
| 実測 | クエリ定義（`Queries.Add`）と接続定義（`CreateModelConnection=False`）は成功。`#table` リテラルのモデル接続は成功（2 行）。ワークシートテーブル参照のクエリはモデル接続作成で 10 分以上停止。ダイアログウィンドウは存在しない |
| 影響 | モデル テーブル名は自動命名（クエリ、クエリ 1）であり COM から改名できない。通常のピボットキャッシュは作成可能 |
| 状態 | 確定（2026-10-21 実測） |
| 再開条件 | 対話セッションで Excel を起動し、手動でクエリをデータモデルへ読み込めることを確認できた環境 |

## D-24 売上分析の方式 A 採用（2026-10-22）

| 項目 | 内容 |
|---|---|
| 決定 | 売上分析は通常のピボットテーブル（共有キャッシュ）、業種・商品スライサー、日付タイムライン、ピボットグラフ、GETPIVOTDATA ヒートマップで構成する |
| 根拠 | D-22 により Power Query・データモデル・DAX は本ビルド環境で実行不能。方式 A は通常 PT とスライサー・タイムラインの実機成立を確認済み |
| 実装 | PT-01 から PT-08、PG-01 から PG-04、SL_業種、SL_商品、TL_日付。共有キャッシュ 1 個 |
| 例外 | PT-07（前年比）と PT-08（前年比較）は前年データを参照するためタイムライン非連動。業種・商品スライサーには接続する |
| 相違 | PQ・DAX・リレーション・CUBE 関数なし。前年比は PT の年別集計で代替。商品マスタは別テーブルだが PT 未接続。万円は計算フィールドと表示形式で実装 |
| 影響 | KPI は円、グラフとヒートマップは万円。タイムライン初期値は 2026 年。2025 年列はタイムラインを全期間へ広げるまで空欄 |
| 検証 | `verify_v04_windows.py` 173 / 173 合格。メモ 74、INDIRECT 24、保護・固定枠なし、VBA・外部リンクなし、absPath 0、ローカルパス 0 |
| 状態 | 確定（v0.4 実装済み） |
